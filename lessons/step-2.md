## Хочу

Выполнить поставку Батча 1 по AWS IAM согласно §5.15 AGENTS.md: перевести посадочную страницу (`ru/index.html`) и первые пять фундаментальных тем (`ru/01.html` - `ru/05.html`) из состояния скелетов в полноценный инженерный справочник без единой строки-заглушки.

Посадочная страница оформляется по каноническому формату серии с заголовком «Практический справочник-ассессмент по AWS IAM для инженера», картой всех 15 глав, шкалой уровней зрелости Noob / Pro / IGL с детальным сравнительным ответом на один вопрос ассессмента, описанием возможностей веб-архитектуры и практическими артефактами. Главы 01-05 закладывают математически точный фундамент понимания IAM:
- `ru/01.html` (Кто решает и по какому правилу): запрос авторизации, контекст (principal, action, resource, environment), структура принятия решений, почему политика - это документ, а не флаг в консоли.
- `ru/02.html` (Язык политики JSON): спецификация грамматики AWS IAM, элементы `Version`, `Statement`, `Effect`, `Action`, `Resource`, `Condition`, `Principal`, правила синтаксиса и строгие типы данных.
- `ru/03.html` (Как вычисляется ответ): детерминированный алгоритм вычисления решения, приоритет явного `Deny` над `Allow`, неявный `Deny` по умолчанию, границы разрешений (boundaries) и сервисные политики контроля (SCP) как пересечение множеств.
- `ru/04.html` (Политика на личности и на ресурсе): сравнение Identity-based и Resource-based политик, поведение внутри одного аккаунта против cross-account доступа, доверие и комбинированная оценка.
- `ru/05.html` (Роли и доверие): сервис `STS`, вызов `AssumeRole`, trust policy (`AssumeRolePolicyDocument`), временные учетные данные против статических долгоживущих ключей, механика инстанс-профилей.

Названия глав фиксируются в навигации сайта, слово поискового смоук-теста в `site.conf` обновляется на `policy`.

## Предикаты

### 1. Контент: шесть страниц написаны, скелетных строк 0, пол по объему не менее 900 слов

Машинные проверки подтверждают качество и целостность разметки:
- `grep -c 'Текст этого раздела ещё не написан' ru/index.html ru/01.html ru/02.html ru/03.html ru/04.html ru/05.html` возвращает строго нули.
- Атрибут `data-words` каждой из страниц `ru/index.html`, `ru/01.html`, `ru/02.html`, `ru/03.html`, `ru/04.html`, `ru/05.html` составляет не менее 900 слов.
- Соблюдена строгая двухуровневая нумерация: на страницах 01-05 все содержательные заголовки `<h2>` следуют шаблону `<h2 id="...">N · Заголовок <a class="anchor-link" href="#...">#</a></h2>`, вводные блоки «Главная мысль страницы» и заключительные «Артефакты» не нумеруются.
- Нет горизонтального переполнения на мобильном вьюпорте 390px и залипания на десктопном 860px.

### 2. Утверждения: манифест tools/claims.tsv содержит не менее 12 проверяемых фактов по темам 01-05

В `tools/claims.tsv` добавлены и проверены запуском утверждения о синтаксисе документов политик, обязательных и опциональных полях, модели вызовов AWS CLI (`--generate-cli-skeleton`, валидация JSON через `python3 -m json.tool` или `jq`, логика вычисления пересечений прав).
Скрипт `./tools/check-claims.sh` завершается с кодом 0 и выводит `ЗЕЛЁНОЕ`.

### 3. Целостность: git diff в границах батча, полный ./check.sh дает ЗЕЛЁНОЕ (9/9)

Полный скрипт валидации сайта `./check.sh` завершается с кодом 0 и выводит статус `ЗЕЛЁНОЕ` по всем 9 проверкам:
- Страница и заголовок
- Оболочка и навигация
- Утверждения сайта проверены запуском
- Примеры со страниц запускаются
- Линейка ссылок
- Текст и пунктуация страниц (без длинных тире U+2014)
- Индекс поиска
- Данные страниц: голова, объем, соседние темы
- Проверка страниц: телефон 390px и липкая панель

Дифф ограничен файлами Батча 1: `ru/index.html`, `ru/01.html` - `ru/05.html`, `tools/claims.tsv`, `site.conf`, перегенерированные служебные блоки (`assets/search-*.js`, навигация, мета-теги) и файлы документации в `lessons/`.
