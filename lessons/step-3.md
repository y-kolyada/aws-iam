## Хочу

Выполнить поставку Батча 2 по AWS IAM согласно §5.15 AGENTS.md: перевести главы 06-09 (`ru/06.html` - `ru/09.html`) из состояния скелетов в полноценные инженерные руководства без единой строки-заглушки.

Главы 06-09 раскрывают продвинутые механизмы безопасности, эшелонированной защиты и диагностики:
- `ru/06.html` (Границы разрешений): Permissions Boundaries, Service Control Policies (SCP) в AWS Organizations, сессионные политики, безопасное делегирование прав создания ролей без риска эскалации привилегий.
- `ru/07.html` (Условия и контекстные ключи): грамматика блока Condition, операторы сравнения (String, Numeric, Date, IP, Bool, Arn, Null, IfExists), глобальные контекстные ключи (`aws:PrincipalArn`, `aws:PrincipalOrgID`, `aws:SecureTransport`, `aws:SourceIp`) и динамические переменные политики (`${aws:username}`).
- `ru/08.html` (Ключи, федерация и машины): эволюция аутентификации вычислительных нагрузок, почему статические ключи пользователей - технический долг, федерация OpenID Connect (OIDC) для GitHub Actions, IAM Roles Anywhere для on-premises, EKS IRSA и EKS Pod Identity.
- `ru/09.html` (Почему доступ запрещён): инженерная методология диагностики `AccessDenied`, декодирование сообщений через `aws sts decode-authorization-message`, аудит событий в AWS CloudTrail, моделирование в IAM Policy Simulator и поиск неиспользуемых прав через IAM Access Analyzer.

Манифест `tools/claims.tsv` пополняется новыми машинно-проверяемыми утверждениями по синтаксису и поведению сервисов 06-09.
