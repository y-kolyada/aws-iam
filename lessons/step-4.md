## Хочу

Выполнить поставку Батча 3 по AWS IAM согласно §5.12 и §5.15 AGENTS.md: перевести главы практических примеров 10-12 (`ru/10.html`, `ru/11.html`, `ru/12.html`) из состояния скелетов в серии проверенных боевых конфигураций и синхронизировать обзорный блок практических примеров на посадочной странице `ru/index.html` снизу вверх на основе фактически написанных сценариев.

Каждая из трех практических глав строится на строгой триаде из 7 сценариев (всего 21 сценарий):
- Постановка задачи в `<p><strong>Задача:</strong> ...</p>`
- Рабочий документ политики или вызов CLI в `<pre><code>...</code></pre>`
- Глубокий разбор внутренней механики в `<div class="prints"><strong>Почему так:</strong> ...</div>`

Распределение по ступеням зрелости:
- `ru/10.html` (Примеры · Noob): базовый фундамент и устранение страха перед IAM (доступ к бакету, домашние папки `${aws:username}`, принудительный TLS, требование MFA для деструктивных действий, доступ к биллингу, ограничение региона `aws:RequestedRegion`, смена паролей).
- `ru/11.html` (Примеры · Pro): командный продакшн и бесключевой доступ (OIDC для GitHub Actions, делегирование создания ролей с Permissions Boundary, Key Policy для KMS и EBS, IRSA для Kubernetes, безопасный cross-account S3 с контролем владения объектами, фильтрация офисного IP с исключением для AWS, гранулярный доступ к Secrets Manager).
- `ru/12.html` (Примеры · IGL): корпоративная архитектура и мульти-аккаунты (геофенсинг регионов через SCP в AWS Organizations, неизменяемость CloudTrail и аудита для root, изоляция периметра VPC Endpoints через `aws:sourceVpc`, фильтрация организации `aws:PrincipalOrgID`, аварийная роль Break-Glass, IAM Roles Anywhere для on-premises серверов, аудит дрифта прав через Access Analyzer).

Посадочная страница `ru/index.html` синхронизируется снизу вверх с точным отражением структуры и содержания всех 21 сценариев.

## Предикаты

### 1. Контент: три практические главы написаны, ровно по 7 сценариев в триаде Задача/Код/Почему так, пол по объему не менее 900 слов

Машинные проверки подтверждают качество и структуру:
- `grep -c 'Текст этого раздела ещё не написан' ru/10.html ru/11.html ru/12.html` возвращает строго нули во всех трех файлах.
- Каждая страница содержит ровно 7 сценариев, оформленных через строгую триаду `Задача`, `pre code`, `div.prints Почему так`.
- Атрибут `data-words` каждой из страниц `ru/10.html`, `ru/11.html`, `ru/12.html` составляет не менее 900 слов.
- Соблюдена строгая двухуровневая нумерация: подразделы следуют шаблону `<h2 id="...">N · Название <a class="anchor-link" href="#...">#</a></h2>` (N от 1 до 7), вводные и заключительные блоки не нумеруются.
- Нет элементов `<table>` (запрещены правилом §5.12 для предотвращения брака на 390px мобильных экранах), проверка `node tools/check-pages.mjs` отвечает `ЗЕЛЁНОЕ` (в браке: 0).

### 2. Утверждения: манифест tools/claims.tsv пополнен минимум 9 новыми фактами по главам 10-12 (по 3 на главу)

В `tools/claims.tsv` добавлены и проверены запуском не менее 9 новых проверяемых утверждений по сценариям глав 10-12 (общее число утверждений не менее 33).
Скрипт `./tools/check-claims.sh` завершается с кодом 0 и выводит `ЗЕЛЁНОЕ`.

### 3. Целостность: обязательная синхронизация ru/index.html снизу вверх, git diff в границах батча, полный ./check.sh дает ЗЕЛЁНОЕ (9/9)

Согласно §5.12 и §7.1 AGENTS.md, посадочная страница `ru/index.html` обязательно синхронизирована снизу вверх и содержит детальное описание всех реализованных сценариев глав 10-12; поставка без диффа в `ru/index.html` признается браком.
Полный скрипт валидации сайта `./check.sh` завершается с кодом 0 и выводит статус `ЗЕЛЁНОЕ` по всем 9 проверкам.
